> **2026-11-18 — R4, run from source (supersedes everything below about installing or running Orkka).** There is no `orkka-local` binary any more: Orkka is a git clone, `./orkka start` (`orkka.cmd` on Windows) builds it and runs ONE foreground process (`dotnet src/Orkka/bin/Release/net10.0/orkka.dll` — the `src/Orkka.Local` host with API, hubs, `/internal/runner/*` relays and the static Vite UI from `ui/apps/local/dist`, plus the in-process runner; SQLite at `~/.orkka/data/orkka.db`). GONE: release downloads and signature verification (`ReleaseVerification`), the newer-release check (`--no-update-check`, `ORKKA_NO_UPDATE_CHECK`), `path add|remove|status`, `--detach`, `start`/`up`/`down` as stack verbs, the default `connect` verb, the supervisor, portable Postgres, the Next.js standalone UI server, YARP, `Orkka.Local.Host`, `Orkka.AppHost`, `Orkka.Worker`, the `orkka-local-cli` distribution repo. > **2026-11-17 update (orkka-api e3a3a06 … 10707ed, orkka-ui 6c17c16 / 8ddcd6f).** Cloud execution is GONE, not dormant: no `ExecutionTarget`/`ExecutionTargetReason` on tasks, no execution preference (`GET|PUT /api/me/execution-preference`), no execution-target preview/switch (`POST /api/projects/{id}/tasks/execution-target`, `POST /api/tasks/{id}/execution-target`), no org `allowHybridExecution`, no project `cloudFallbackAfterMinutes`, no cloud fallback sweep / provider capacity gate / free-tier ceiling / cloud jobs, forecasts are time-only (cost always null, no `executionTarget*`), admin usage has no `cloudExecutions`/`localExecutions`. Every task runs on its owner's runner (`RunnerUserId`); `IRunnerCoverageResolver` only explains whether that runner has the model's provider. Orkka stores no code: code-change snapshots keep paths/counts/hash, `GET /api/tasks/{id}/code-changes/{snapshotId}` reads the diff live from the runner (`currentBranch`, `unavailable`); commit history carries no `authorEmail`. Runner tokens expire after 90 days (`expiresAt` in list/create) and renew while connected (hub `RotateToken`). The runner vets every repository command (`command-trust`: orkka.json on the default branch or `./orkka commands approve <id>`; refusals post a task-thread note), has no remote terminal, streams no tool results, always enforces the agent guard, treats Gemini/Grok/OpenCode as not ready unless `ORKKA_ALLOW_UNGUARDED_PROVIDERS` lists them in `~/.orkka/runner.env`, keeps its token in the OS secret store, and only `./orkka update` (signature-verified) replaces the binary — `connect` just reports a newer release (`--no-update-check` / `ORKKA_NO_UPDATE_CHECK`). ## 6. Auth & API wiring
`packages/core/src/lib/api.ts`: base `NEXT_PUBLIC_API_URL` (server: `ORKKA_INTERNAL_API_URL` override; mobile `EXPO_PUBLIC_API_URL`); every request sends `Authorization: Bearer ${token}`, `Accept-Language`, `X-Orkka-Country`, `cache: no-store`. `ApiError(status, body)`; `extractErrorMessage()` parses FastEndpoints ProblemDetails; `planLimitFrom()` maps HTTP 402 `code ∈ {plan_limit_projects, plan_limit_seats, plan_limit_repos, plan_requires_team}` to upgrade prompts. Browser GET cache with in-flight dedup + opt-in TTL; mutations call `invalidateApiCache()`. Token: remote client `apps/remote/hooks/use-client-api.ts` → Clerk `useAuth().getToken()`; server `auth()` → `getToken()` (redirect `/sign-in` when null); SignalR `ClerkSignalRProvider.tsx`; local = constant `"local"`. Env names: `NEXT_PUBLIC_API_URL`, `ORKKA_INTERNAL_API_URL`, `EXPO_PUBLIC_API_URL`, `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `NEXT_PUBLIC_RUNNER_HUB_URL`. Router cache `staleTimes: {dynamic: 30, static: 300}` (`apps/remote/next.config.ts`).
